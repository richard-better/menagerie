Menagerie master plan v1

Richard Borcsik · 26 November 2026 · richard-better/menagerie

Menagerie is an open-source Mac app for a handful of long-lived personal machines. It shows each machine's health, its services and how far its configuration is ahead of or behind the repo, and syncs it in one click.

1. Principles

Menagerie is for pets, not cattle: 2 to 10 named machines that live for years, not hundreds that come and go.

  • Each machine is an individual. It has a name, a role, its own services and quirks.
  • You decide when to sync. Watching is optional. A sync can run in the background and tell you when it's done, or you can follow it live.
  • Rolling back matters more than rolling out. You can't throw a pet away, so the previous generation is always one click away.
  • No scale machinery. The network is the security boundary. No sign-in system, no high availability, no orchestration.
  • Nix-first, not Nix-only. Nix users get everything generated. Anyone else can write the fleet file by hand.

2. Architecture

Reads go over HTTP to a small read-only agent on every machine. Writes go over SSH, or run locally on the Mac the app is on.

  • fleet.yaml says which machines exist, how to reach them, how to sync them, and which services they expose.
  • The agent runs on every machine. It only reads and reports. It never runs commands on request.
  • The app reads the fleet file and polls each agent. It is the only thing that writes.
  • Hostnames are plain hostnames. Tailscale MagicDNS names work, and so does a LAN name or IP. Nothing requires Tailscale.

3. The fleet file

One YAML file, versioned from the first commit. JSON is valid YAML, so a Nix-generated JSON file works as-is. In a Nix setup, services can be declared next to the service in Nix, but they always end up in this file.

version: 1
machines:
  richard-m4-max:
    role: Primary workstation
    device: laptop
    agent: http://richard-m4-max:9184
    sync: { preset: nix-darwin, repo: ~/dev/gh/richard-better/mac }

  richard-hp-server:
    role: Media server, exit node
    device: laptop
    agent: http://richard-hp-server:9184
    ssh: richard@richard-hp-server
    sync: { preset: home-manager, repo: ~/dev/gh/richard-better/mac }
    services:
      - name: Jellyfin
        icon: jellyfin
        url: http://richard-hp-server:8096
        health: http://richard-hp-server:8096/health
      - name: Jellyseerr
        icon: jellyseerr
        url: http://richard-hp-server:5055

  homeassistant:
    role: Smart home
    device: box
    services:
      - { name: Home Assistant, icon: home-assistant, url: http://homeassistant:8123 }
  • Sync presets: nix-darwin, nixos, home-manager, or a custom command.
  • Icons are keys into the bundled dashboard-icons set.
  • A machine without an agent (Home Assistant above) still shows its online status and service icons.
  • Nix integration ships from Menagerie's flake: modules that add menagerie.* options and a lib.mkFleet that turns a flake's configurations into the fleet file.

4. The agent

A small Rust binary, in the fleet from day one. Probes refresh a cache on their own schedules. HTTP requests only read the cache, so they always answer in under a millisecond.

ProbeHow it refreshes
Load, CPU, memoryevery 5 s
Battery, charging, temperatureevery 30 s, or on power events
Disk freeevery 5 min
Applied revision, generation, dirty flagwhen the current-system or Home Manager link changes, plus hourly
Service health (services on this machine)every 30 s
Uptime, OS versionat start
  • /status returns JSON. Every value carries the time it was measured, and the agent's own clock is included, so the app can show how old each value is.
  • /metrics returns Prometheus format with node_exporter's metric names, so Grafana dashboards work unchanged.
  • After sleep it re-runs every probe at once instead of serving stale values.
  • A failing probe keeps its last good value and adds an error.
  • Exposure: by default it listens on one address and port given in its config. tailscale serve can publish it over HTTPS, and it can expose several ports or paths per machine, so it works alongside other services. No tsnet.
  • Packaging: built by Nix on each machine, plus signed release binaries for everyone else.

5. The app

Two views over the same data: a compact menu bar popover for a glance, and a full window for everything else. Dark, with dot-matrix charts and meters, monospace numbers, and colour only where it means something.

Full window

The machine strip sits at the top. Selecting a machine switches the panel below, which holds its health, its services (one click to open) and its sync controls.

  • The menu bar icon carries the state: plain when everything is in sync, a count of machines that need attention, a spinner while syncing, red when a sync failed.
  • One status vocabulary in both views: a dot before the name (green in sync, amber needs attention, grey no agent, hollow offline) and the same words after it.
  • No telemetry in the glance. Load and battery appear here only when they are the reason for attention.
  • Open Menagerie and Settings are small icons in the top right. A machine that needs a sync gets one quiet button showing its ahead/behind arrows and a sync icon. Sync all appears as a third icon only when two or more machines need it. It runs in the background and sends a notification when done.
  • All numbers in these mockups are placeholders.

6. Sync model

Three revisions are compared: what each machine has applied, your local checkout's HEAD, and origin/main. Ahead and behind are shown like git: ↑2 ↓5.

  • Your checkout shows unpushed commits and a dirty working tree.
  • Each machine shows how far its applied revision is behind origin/main, and whether it is ahead (built from local or uncommitted changes).
  • Sync handles both directions: it pushes your unpushed commits if the tree is clean, then the machine pulls, builds and switches. It refuses on a dirty tree and says why.
  • Sync always runs in the embedded terminal, visible or not. On your Mac, sudo asks for Touch ID. On another machine, a password prompt appears in the terminal. A passwordless rule for just the rebuild command is an optional extra for fully one-click syncs.
  • Roll back switches to the previous generation the same way.

7. Decisions

#TopicDecision
1LicenseMIT
2App stackRust with gpui. Upstream gpui has no menu bar item API, so a spike comes first (see milestone 0).
3On each machineOur own Rust agent from day one: /status JSON and /metrics with node_exporter names.
4Public interfaceThe YAML fleet file, versioned from the first commit. Nix is one way to produce it.
5Services and linksListed in the fleet file. In a Nix setup they can be declared in Nix, but they end up in the YAML.
6Reads and writesReads over HTTP from the agent, writes over SSH or locally.
7NetworkAny hostname. Tailscale is the expected default but not required. No tsnet.
8Privileged syncRuns in the embedded terminal: Touch ID locally, password prompt remotely.
9UIMenu bar popover plus full window with a machine strip. Dark, dot-matrix.
10Ahead and behindTwo-way, against your checkout and origin/main. Sync handles both.
11DistributionSigned and notarized with your Developer ID, shipped through your Homebrew tap.
12HistoryOptional. Grafana can scrape /metrics. Not part of the core.

8. Open questions

  • Menu bar on gpui: use the gpui-tray crate, the adabraka-gpui fork, or our own NSStatusItem through objc2 with a gpui window as the popover? The spike decides.
  • Embedded terminal on gpui: Zed's own terminal is built on alacritty_terminal; we would likely reuse that approach.
  • Service health: does the agent check its own machine's services, or does the app check every service URL directly? The agent is better for machines the app can't reach on every port; the app is the only option for machines without an agent.
  • Changes view: its own window, a sheet, or a tab in the main window?
  • Machines without an agent (Home Assistant, the iPhone): online status comes from where? Tailscale's local API is the easy answer, but then it isn't Tailscale-optional for those.

9. Milestones

  1. gpui spike. A menu bar icon with a popover, a window with the machine strip, and an embedded terminal running a shell. Decides decision 2 for good.
  2. Agent and fleet file. The Rust agent with cached probes, /status and /metrics. The fleet file schema with version: 1.
  3. Nix integration. Modules and lib.mkFleet in Menagerie's flake. In the mac repo: stamp each generation with its commit, run the agent on the Mac and the HP server, generate the fleet file.
  4. Read-only app. Menu bar and window against real data from the two machines.
  5. Sync. Ahead and behind, Sync, Roll back, the terminal, notifications.
  6. Release. Signed and notarized build, Homebrew cask, agent release binaries, README.
